Part A — Basic Questions

What are the base case and recursive case for your factorial?

The base case for factorial is n <= 1, which returns 1. This stops the recursion.

The recursive case is n * factorial(n - 1). Each recursive call decreases n by 1, so the function eventually reaches the base case.

What goes wrong if you omit the base case?

If the base case is omitted, the recursive function will keep calling itself without stopping. This can eventually cause a stack overflow because the program keeps adding function calls to the call stack.

When might a loop be a better fit than recursion for summing an order?

A loop can be a better fit when the problem is simply processing a list of items from beginning to end. A loop avoids the extra function calls and stack usage caused by recursion. For a straightforward order, a loop is often simpler and more efficient.

Part B — Function Pointers

What does a function pointer store?

A function pointer stores the address of a function. It allows the program to call a function through the pointer.

How can apply_op stay unchanged while the cafe changes which pricing rule runs?

apply_op takes a function pointer as one of its parameters. The caller can pass different functions, such as add_cents or percent_off_amount. Because apply_op calls whichever function is passed to it, apply_op itself does not need to change when the pricing behavior changes.

Name one real-world callback example that you can think about or learn about.

A button click handler in a graphical user interface is an example of a callback. The program can store a function that should run when the user clicks a button. Another example is a sorting function that accepts a comparison function to decide how two values should be ordered.

Why is a hand trace useful before you chase a recursive bug in the debugger?

A hand trace helps me understand exactly how the recursive calls should work before using a debugger. It makes the base case, recursive case, arguments, and return values easier to see. If the program gives the wrong result, I can compare the actual behavior to the hand trace and identify where the recursion went wrong.

The sum_order function demonstrates that recursion can work through an array as well as through a number. Each call processes the first remaining price and then recursively processes the rest of the array.
