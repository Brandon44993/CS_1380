PART A — BASIC QUESTIONS

1. Where did you use while versus do-while, and why?

I used while loops to validate the inputs because the user may need to enter an unknown number of attempts before entering valid input. A while loop works well because it can continue until the input is valid.

2. Why does re-prompting fit those loops better than a for loop?

The number of invalid attempts is not known ahead of time. A while loop is better because it continues based on a condition rather than a predetermined number of repetitions.

3. What happens if you do not clear the input buffer after a failed scanf("%d", ...)?

If scanf fails because the user enters something that is not an integer, the invalid characters remain in the input buffer. The next scanf can encounter the same invalid characters and fail again, which can cause an infinite loop of error messages. Clearing the remaining characters up to the newline allows the user to enter new input.

4. What happens if you use the wrong scanf format specifier?

Using the wrong format specifier can cause scanf to interpret the input incorrectly or write data to the wrong type of variable. This can produce incorrect results and can cause undefined behavior.

PART B — BASIC QUESTIONS

1. Why is a for loop natural when you know exactly how many customers to process?

A for loop is natural because the number of customers is known before the loop starts. The loop can run exactly once for each customer from 1 through n.

2. Where did you use continue? What would happen if you used break instead?

I used continue when a customer is under 13 and therefore ineligible. The program prints that the customer is not eligible, increases the ineligible count, and uses continue to move to the next customer.

If break were used instead, the entire for loop would end immediately. Any remaining customers would not be processed, so the final totals would only include the customers processed before the break.
