Part A — Basic Questions
1. If p is an int *, why does p + 1 usually add 4 bytes? What if p is a char *?

Pointer arithmetic advances by the size of the type that the pointer points to. If p is an int * and an int occupies 4 bytes on the system, p + 1 advances by 4 bytes to the next integer. If p is a char *, p + 1 advances by one byte because a char occupies one byte in C.

2. What does end - start mean when both pointers point into the same integer array?

It gives the number of integer elements between the two pointers, not the number of bytes. For example, if start points to element 0 and end points to element 4, end - start is 4.

3. Why is *(prices + 5) undefined behavior for an array of length 5, even if it compiles?

An array of length 5 has valid indexes from 0 through 4. The expression prices + 5 points one element past the end of the array. That pointer may be used as a boundary, but it must not be dereferenced. Dereferencing it accesses memory outside the array and causes undefined behavior.

Part B — Hand Trace

Given:

int arr[] = {10, 20, 30, 40, 50};
int *p = arr + 2;


The pointer p points to arr[2], which contains 30.

*p = 30
*(p + 1) = 40
*(p - 1) = 20
(arr + 4) - p = 2

The final result is 2 because the pointer to arr[4] is two elements after the pointer to arr[2].

4. How does drink_length know when to stop without being passed a length?

A C string ends with the null character '\0'. The function advances its pointer while the character is not '\0'. When it reaches the terminator, it stops and subtracts the starting pointer from the current pointer to calculate the string length. The terminator itself is not counted.

5. When is a subscript such as prices[i] clearer than pointer increment, and when is a p++ walk a good fit?

Array subscripting is clearer when I want to access a specific element by its index, such as prices[2]. A p++ pointer walk is useful when traversing an entire array in order. It demonstrates how pointers move between elements and works well with pointer-comparison loop conditions.

6. Why is a one-line hand trace useful before debugging a bad pointer?

A hand trace lets me check exactly where a pointer points and what each expression should produce. It can reveal an incorrect offset, an off-by-one error, or an attempt to access memory beyond the array before I spend time using a debugger.
